CI/CD & Docker pipeline — painel real, cache e segurança frontend

Documento de referência da seção [ LIVE CI/CD & DOCKER PIPELINE ] do portfólio. Cobre (1) a arquitetura real dos workflows do repositório, (2) o resumo executivo orientado ao cliente e o detalhamento colapsável, (3) como o frontend consome os metadados públicos do GitHub Actions, (4) cache e rate-limit, (5) os controles de segurança aplicados no cliente e (6) como validar tudo localmente.

Versão renderizada (é o alvo do link [ documentação técnica ] do portfólio): docs/ci-cd-pipeline.html. O Markdown continua sendo a fonte.

Escopo: somente metadados públicos, somente leitura. Nenhum token, segredo ou credencial é embutido, solicitado ou enviado pelo frontend.

Contratos preservados: ascii-engine-module/, assets/js/ascii-engine.bundle.js e assets/js/engine-adapter.js não foram alterados. O valor interno mode: 'playground' do adapter é contrato da engine 3D e continua igual; o que saiu do portfólio foi apenas o texto “Playground” de títulos, rótulos e metadados.

GET https://api.github.com/repos/yamamotin/AncientStudio/actions/workflows

3. Cache, rate-limit e fallback informativo

  • TTL de dados: 300000 ms (5 minutos) em localStorage sob a chave tp.gh-actions.v1. Se o storage estiver bloqueado (file://, modo privado, cota cheia) o estado continua em memória — o painel nunca depende do storage.
  • Cache defensivo: o conteúdo lido do storage é re-sanitizado com sanitizeRuns() antes de renderizar, então um cache adulterado não injeta URL ou campo inválido.
  • Rate-limit não autenticado: 60 requisições/hora por IP. O painel lê x-ratelimit-remaining e x-ratelimit-reset; abaixo de 10 restantes a cota aparece na linha de status, e um 403/429 mostra a mensagem de limite com o horário de renovação.
  • Fallback informativo: em falha de rede, timeout ou rate-limit, o painel mantém os últimos dados em cache (marcados como cache, com a idade em segundos) e informa quando a API volta a responder. Links externos por execução não existem mais: a única URL externa do painel é o link allowlisted da última execução, dentro da documentação técnica, e a referência https://github.com/yamamotin/AncientStudio/actions no <noscript>.
  • Timeout: AbortController com 8 s por requisição; o timer é sempre limpo no finally. A mesma regra vale para o resto do frontend: 10 s em /api/v1 (api-client.js), 5 s no probe api-status.json, 4 s no dicionário i18n — nenhuma chamada fetch fica sem limite de tempo.
  • Anti-flood: state.loading impede requisições concorrentes, o botão fica desabilitado com aria-busy="true" durante a chamada e existe um cooldown de 4 s entre tentativas manuais (clique duplo ou repetido não gera tráfego extra).

4. Monitor compacto orientado ao cliente

A seção deixou de ser uma lista de links e virou uma tela de monitoramento compacta:

  • Resumo executivo sempre visível (#pipeline-summary, quatro cartões preenchidos apenas com dados reais da API): última execução (status · HH:MM UTC), confiabilidade (sucessos/concluídas · %), higiene das imagens Docker (última execução do vcr-cleanup.yml, política das 3 imagens mais recentes) e quantidade de workflows monitorados.
  • Sem links repetidos por item: cada linha da lista mostra nome, selo de status, branch, SHA curto, duração e timestamp. O [ abrir run ] de cada execução e o botão [ open actions ] foram removidos; sobrou apenas [ atualizar ].
  • Ruído interno filtrado: execuções do Auto-merge verified PRs e conclusões skipped/cancelled não entram no resumo nem na lista. Quando algo é filtrado, a nota #pipeline-filter-note explica o critério (pipeline.filtersNote).
  • Detalhamento colapsável: o corpo (#pipeline-body) guarda a lista de execuções, a nota de filtro, o <noscript> e o bloco [ documentação técnica ]. O painel abre recolhido (data-collapsed="true") para não empurrar o resto do portfólio.
  • Sem fabricação de dados: o cliente nunca inventa status, imagens ou contagens; se a API não responde, os cartões mostram o último valor carregado ou —.

A mesma política de altura compacta vale para as seções altas do portfólio que não são o palco 3D: #pipeline e #gateway abrem recolhidas e #stack, que é curta, abre expandida. O mecanismo é único: [data-collapsible] + [data-collapse-toggle] + .collapse-body.

Exceção deliberada — #scene: a cena 3D é o ativo visual principal e fica sempre montada e expandida. Ela não tem data-collapsible, não tem botão de recolher/expandir e não tem #scene-body recortável; por isso o engine-adapter.js monta o palco assim que a seção entra no viewport, sem depender de um clique para "abrir". Os controles da cena continuam intactos: barra de fonte/célula com [ restaurar ], presets [ Dia ], [ Noite ], [ Com chuva ], [ pause ], [ tela cheia ] e zoom por scroll do mouse.

Detalhes de implementação relevantes:

  • Recolher uma seção não destrói nem remede a cena 3D quando ela está envolvida: o mecanismo só recorta por max-height, mantém o contrato público (engine-adapter.js, ascii-engine.bundle.js) e o ResizeObserver do adapter válido. A cena em si nunca é envolvida — ver a exceção abaixo.
  • O fullscreen da cena não mexe mais no mecanismo de colapso: desde que a seção passou a ser sempre expandida, não existe clamp para suspender.
  • Rótulos traduzidos em pt-br e en (common.expand / common.collapse), presentes nos dois JSON e no dicionário embutido BUNDLED.

5. Segurança no cliente

5.1 Zero segredos

  • Nenhum GITHUB_TOKEN, VERCEL_TOKEN, chave de API ou credencial em assets/js/**, index.html ou dicionários.
  • A chamada é pública: credentials: 'omit' e nenhum header de autorização.
  • A chave de API digitada na UI (#workflow-token) é type="password", autocomplete="new-password", marcada com data-sensitive="true", nunca é gravada em storage e é apagada em pagehide e em visibilitychange → hidden (initSensitiveInputs() em assets/js/main.js).
  • O formulário público de consulta PROJUDI (Gateway → ETL/Integrações) recebe um CPF validado por mod-11. Esse campo é data-sensitive="true", sem autocomplete, sem spellcheck, e a regra é genérica: nenhum input[data-sensitive] é gravado em storage, todos são limpos em pagehide/aba oculta e ficam mascarados quando fora de foco (input[data-sensitive]:not(:focus) { -webkit-text-security: disc }). O valor só viaja no corpo da própria requisição para /api/v1/projudi/*, nunca é ecoado no painel de resposta nem no console. A máscara definitiva de exibição LGPD (***.456.789-**) é aplicada no servidor.
  • O runner fictício saiu do cliente: TP.api.runPipeline foi removido e o painel nunca dispara builds. O endpoint POST /api/v1/pipeline/run continua existindo apenas no backend legado, com seus próprios testes, sem uso pela interface.

5.2 Proteção contra XSS e injeção de DOM

  • Toda renderização usa document.createElement + textContent. Não existe innerHTML, outerHTML, insertAdjacentHTML ou document.write com dado externo.
  • text(value, max) coage qualquer valor a string, remove caracteres de controle e marcas de direção Unicode (\u202a–\u202e, \u200b–\u200f), normaliza espaços e limita o tamanho (96 caracteres por padrão; 72 para nomes).
  • safeRunUrl() é uma allowlist estrita: ^https://github.com/yamamotin/AncientStudio/actions/runs/\d{1,20}$. Qualquer outro valor — javascript:, outro repositório, path traversal, host da API — retorna string vazia e o link simplesmente não é criado.
  • sanitizeRun() só aceita status/conclusion no formato [a-z_]{3,24}, SHA hexadecimal e timestamps ISO YYYY-MM-DDTHH:MM:SSZ; o resto é descartado.
  • Todo elemento externo criado recebe target="_blank" + rel="noopener noreferrer". O link da última execução (#pipeline-last-run-link) fica hidden até existir uma URL que passe na allowlist; sem URL válida, href, target e rel são removidos.

5.3 CSP e higiene de requisições

index.html declara, via <meta http-equiv="Content-Security-Policy">:

default-src 'self'; base-uri 'self'; object-src 'none'; script-src 'self';
style-src 'self'; img-src 'self' data:; font-src 'self';
connect-src 'self' https://api.github.com; form-action 'self'; frame-src 'none'
  • Sem unsafe-inline e sem unsafe-eval: não há script inline, o CSS é externo e o bundle da engine não usa eval/new Function.
  • connect-src limita as chamadas de rede ao próprio site (/api/v1, api-status.json) e ao host público do GitHub.
  • <meta name="referrer" content="strict-origin-when-cross-origin"> evita vazar a URL completa do portfólio em navegações externas.
  • Decisão consciente: não foi criado vercel.json com headers de segurança, para não alterar a configuração de deploy do projeto (o ambiente Vercel é usado apenas para verificação). Headers HTTP definitivos ficam no middleware do backend (backend/app/core/middleware.py); a CSP em <meta> já vale para GitHub Pages e Vercel sem tocar em infraestrutura.
  • rel="noopener noreferrer" em todos os links externos do HTML (LinkedIn, Actions, documentação).

6. Documentação: por que existe um HTML

O link [ documentação técnica ] apontava para docs/ci-cd-pipeline.md. Servidores estáticos (api/server.py na Vercel e o Pages) entregam .md como text/markdown/text/plain: o navegador baixa o arquivo ou mostra texto cru, sem índice, sem tabelas. Não havia router JS nem renderer de Markdown no cliente — interceptar o link não resolveria nada.

Correção aplicada em duas partes:

  1. Formato: docs/ci-cd-pipeline.html é uma renderização estática, autocontida (css inline, sem script, sem dependência externa) do mesmo conteúdo, versionada junto com o Markdown. O link do painel (#pipeline-doc-link) aponta para docs/ci-cd-pipeline.html, um caminho relativo que funciona em file://, no GitHub Pages (/AncientStudio/docs/...) e na Vercel. A página inclui um link de volta para o Markdown fonte no GitHub.
  2. Empacotamento: docs/ não era publicado em nenhum dos dois hosts — o staging do Pages copiava só index.html robots.txt sitemap.xml api-status.json assets e o Dockerfile usado pela Vercel copiava apenas assets e api. Agora pages.yml copia docs para _site (com test -f _site/docs/ci-cd-pipeline.html) e o Dockerfile faz COPY docs ./docs (com test -f ./docs/ci-cd-pipeline.html), então o mesmo caminho relativo resolve nos três ambientes.

English summary

The [ LIVE CI/CD & DOCKER PIPELINE ] section replaced the old fake simulator. It reads only public, read-only GitHub Actions metadata for yamamotin/AncientStudio (/actions/runs?per_page=6 and /actions/workflows), renders workflow name, branch, short SHA, status/conclusion, duration, UTC timestamp and the direct run link, and never sends credentials (credentials: 'omit', no Authorization).

The section is now a compact, collapsible monitoring screen: an always-visible executive summary (latest run, reliability, Docker image hygiene, monitored workflows) plus a filtered run list inside a collapsed body, with a single [ refresh ] action and an [ expand ] / [ collapse ] control translated in every locale. Per-run [ open run ] links and the [ open actions ] button were removed on purpose. The 3D scene section is the documented exception: it is always mounted and expanded, with no collapse control, so the engine never waits for an expand gesture.

The technical documentation link now opens docs/ci-cd-pipeline.html, a self-contained static rendering served correctly by GitHub Pages and Vercel (raw .md was being downloaded as plain text). The Markdown file remains the source.

A five-minute localStorage cache (validated again on read), an 8 s AbortController timeout, an in-flight lock plus a 4 s cooldown protect both the visitor and the public API rate limit; failures degrade to cached data plus a direct link to the Actions page.

All external values are coerced to bounded, control-character-free strings and inserted with createElement/textContent; href is allowed only when it matches https://github.com/yamamotin/AncientStudio/actions/runs/<id>, and external links use rel="noopener noreferrer". A <meta> CSP restricts scripts, styles, fonts and images to 'self' and network access to 'self' plus https://api.github.com. No vercel.json was added, deliberately avoiding deployment-config changes.
