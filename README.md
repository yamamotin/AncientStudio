# Eron Terminal — portfólio técnico interativo

Single-page, sem frameworks e sem build: HTML, CSS e um pouco de JavaScript puro com estética de terminal Linux. Inclui banner ASCII, simulador de CI/CD com um caminho de falha e RCA, playground de APIs em abas, bloco de stack estilo `neofetch` e console de comandos (`help`, `skills`, `experience`, `projects`, `contact`, `cv`, `clear`). Tudo o que aparece nos simuladores é fictício e sinalizado como tal.

Para editar, altere `index.html` (textos e ordem das seções), `assets/css/style.css` (variáveis no topo) e os módulos em `assets/js/`. Os currículos enviados pelo Eron estão em `assets/cv/`, e o JetBrains Mono usado localmente está em `assets/fonts/` com sua licença OFL — nada é carregado de CDNs.

Abra `index.html` diretamente para ver a versão em modo sim. A API Python real está em `backend/`: rode `cd backend && uvicorn app.main:app --reload`. Ela expõe `/api/v1/health`, `/api/v1/build`, `/api/v1/etl/datasets`, `/api/v1/etl/datasets/{dataset}/summary`, `/api/v1/etl/datasets/{dataset}/records`, `/api/v1/gateway/invoices/parse`, `/api/v1/gateway/invoices/submit`, `/api/v1/workflows/{workflow_id}/run` e `/api/v1/workflows/runs/{execution_id}`. O servidor legado `api/server.py`, usado pelo `Dockerfile` da raiz na Vercel, continua servindo os endpoints do playground simulado. Testes automatizados de backend e segurança: `cd backend && pytest` e `python3 -m unittest discover -s tests -p "test_*.py" -v`. Com Docker: `docker build -t eron-terminal . && docker run -p 8000:8000 eron-terminal`.

Publicação: `.github/workflows/pages.yml` publica em `https://yamamotin.github.io/AncientStudio/` o mesmo commit de `main` que a Vercel usa. Em GitHub → Settings → Pages → Build and deployment → Source, mantenha **GitHub Actions**. A Vercel usa o `Dockerfile` (projeto `ancientstudio`, `https://ancientstudio.vercel.app/`); as duas hospedagens entregam exatamente os mesmos arquivos relativos. O job `verify-parity` roda **depois** do deploy, compara `build.txt` do Pages com `/api/v1/build` da Vercel e usa `continue-on-error: true`: divergência ou atraso de CDN gera aviso, nunca falha o deploy. PRs verdes são mesclados automaticamente por `.github/workflows/auto-merge.yml`; detalhes das configurações necessárias em `docs/cicd-auto-merge.md` e `docs/pages-recovery.md`.

Idiomas: `pt-br` é o padrão; o botão `[ en ]` no topbar troca rótulos e mensagens sem reload. Dicionários em `assets/i18n/`, com fallback embutido para `file://`. `assets/js/api-client.js` é a camada real de integração com `/api/v1` (ETL, gateway e n8n), sem respostas simuladas.

Testes: `.github/workflows/pr-tests.yml` roda `node --test tests/*.test.js` (contratos estáticos, i18n, CI e motor); `cd backend && pytest` e `ruff check .` validam a API FastAPI; `cd ascii-engine-module && npm ci && npm run typecheck && npm run build` valida o motor isolado. O workflow `.github/workflows/ci.yml` executa essa matriz completa.

Backend real: `backend/` contém a aplicação FastAPI em monólito modular, com domínios em `backend/app/domains/`, cache/fila Redis, workers no lifespan, rate limit, ETL, gateway fiscal com HMAC/idempotência, scrapers, pipelines de IA e integração autenticada com n8n. Além dos endpoints listados acima, há `/api/v1/jobs`, `/api/v1/scraping`, `/api/v1/ai-workflows` e `/api/v1/pipelines`. `docker-compose.yml` sobe API + n8n com segredos obrigatórios em `.env`. O `Dockerfile` da raiz ainda publica a versão atual na Vercel; `ci-cd.yml` constrói apenas a imagem do backend.

O palco `[ ASCII REALMS // SCENE ]` usa o motor WebGL2 3D de `ascii-engine-module/` (`assets/js/ascii-engine.bundle.js`) por meio de `assets/js/engine-adapter.js`, incluindo cenário cyberpunk em camadas, sombras PCF, vento ECS, bloom e DoF. A UI expõe apenas três modos de cena — `[ Dia ]`, `[ Noite ]`, `[ Com chuva ]` — ligados a `setPreset()`; o engine também oferece contorno por objeto (`setObjectOutline`), ainda não aplicado ao pinguim. `[ STACK // NEOFETCH ]` renderiza Tux 3D com `THREE.Group` via `getScene()` e fallback por raycaster em `assets/js/neofetch.js`, com rotação horizontal contínua e nenhuma reação a mouse/toque. O wrapper do adapter expõe `create`, `mount`, `setPaused`, `setPreset`, `setAutoOrbit` e `destroy`, usa `ResizeObserver` e pausa cenas fora da viewport. Nenhum núcleo do motor é alterado pela integração.

O hero mostra a foto/retrato como cartão à esquerda, abaixo de `ERON YAMAMOTO`, servindo de margem para o texto de identidade e as ações. No footer há o controle de brilho da página (padrão `110%`, faixa `100–130%`), que substitui o antigo controle de contraste.
