# Eron Terminal — portfólio técnico interativo

Single-page, sem frameworks e sem build: HTML, CSS e um pouco de JavaScript puro com estética de terminal Linux. Inclui banner ASCII, painel de CI/CD & Docker alimentado por dados reais e públicos do GitHub Actions, gateway de APIs em abas, bloco de stack estilo `neofetch` e console de comandos (`help`, `skills`, `experience`, `projects`, `contact`, `cv`, `clear`). O painel de pipeline não simula nada: resume o estado real do repositório em um resumo executivo (última execução, confiabilidade, higiene das imagens Docker e workflows monitorados) com a lista detalhada dentro de um bloco recolhível. As seções altas (`pipeline`, `gateway`, `stack`) são compactas por padrão, com controle `[ expandir ]` / `[ recolher ]` traduzido em pt-br e en; a cena 3D fica sempre montada e expandida, sem controle de recolher (detalhes em [`docs/ci-cd-pipeline.html`](docs/ci-cd-pipeline.html), fonte em [`docs/ci-cd-pipeline.md`](docs/ci-cd-pipeline.md)).

Para editar, altere `index.html` (textos e ordem das seções), `assets/css/style.css` (variáveis no topo) e os módulos em `assets/js/`. Os currículos enviados pelo Eron estão em `assets/cv/`, o JetBrains Mono usado localmente está em `assets/fonts/` com sua licença OFL, a cena 3D compactada com Draco + WebP (`1024px`) está em `assets/models/cena_completa.glb` e o decoder oficial Draco self-hosted (`draco_decoder.js`, `draco_decoder.wasm`, `draco_wasm_wrapper.js`) está em `assets/draco/` (consumido via caminho relativo `./assets/draco/`, compatível tanto com `/AncientStudio/` no GitHub Pages quanto com `/` na Vercel) — nada é carregado de CDNs.

Abra `index.html` diretamente para ver a versão estática/contingência (o painel de pipeline funciona porque consulta a API pública do GitHub). A API Python real está em `backend/`: rode `cd backend && uvicorn app.main:app --reload`. Ela expõe `/api/v1/health`, `/api/v1/build`, `/api/v1/bcb/{indicadores,instituicoes}`, `/api/v1/siscomex/ncm` (pesquisa integrada Classif: Nomenclatura NCM + Soluções de Consulta COSIT/COANA + Sugestões técnicas, resolvendo termos como `"GPU"`), `/api/v1/transparencia/municipio` (governança IBGE/TSE + PIB, execução orçamentária Siconfi DCA e finanças eleitorais em `BRL`), `/api/v1/projudi/processos/{consulta,{numero},{numero}/resumo}` (raspagem real da consulta pública do PROJUDI/TJPR sem mocks, com retorno `422 CAPTCHA_REQUIRED` quando ausente `captcha_token`), `/api/v1/etl/datasets*`, `/api/v1/gateway/invoices/*` e `/api/v1/workflows/*` (contratos detalhados em [`docs/api-reference.md`](docs/api-reference.md)). O servidor `api/server.py`, usado pelo `Dockerfile` da raiz na Vercel, compartilha exatamente os mesmos conectores `api/connectors/`. Testes automatizados de backend e segurança: `cd backend && pytest` e `python3 -m unittest discover -s tests -p "test_*.py" -v`. Com Docker: `docker build -t eron-terminal . && docker run -p 8000:8000 eron-terminal`.

Publicação: `.github/workflows/pages.yml` publica em `https://yamamotin.github.io/AncientStudio/` o mesmo commit de `main` que a Vercel usa. Em GitHub → Settings → Pages → Build and deployment → Source, mantenha **GitHub Actions**. A Vercel usa o `Dockerfile` (projeto `ancientstudio`, `https://ancientstudio.vercel.app/`); as duas hospedagens entregam exatamente os mesmos arquivos relativos. O job `verify-parity` roda **depois** do deploy, compara `build.txt` do Pages com `/api/v1/build` da Vercel e usa `continue-on-error: true`: divergência ou atraso de CDN gera aviso, nunca falha o deploy. PRs verdes são mesclados automaticamente por `.github/workflows/auto-merge.yml`; detalhes das configurações necessárias em `docs/cicd-auto-merge.md` e `docs/pages-recovery.md`.

Idiomas: `pt-br` é o padrão; o botão `[ en ]` no topbar troca rótulos e mensagens sem reload. Dicionários em `assets/i18n/`, com fallback embutido para `file://`. `assets/js/api-client.js` é a camada real de integração com `/api/v1` (ETL, gateway, n8n, pipelines e console RAG), sem respostas simuladas; `assets/js/pipeline.js` consome apenas metadados públicos e read-only do GitHub Actions, com cache, timeout e allowlist de URLs.

Testes: `.github/workflows/pr-tests.yml` roda `node --test tests/*.test.js` (contratos estáticos, i18n, UI, CI/auto-merge e motor); `cd backend && pytest` e `ruff check .` validam a API FastAPI (66 testes unitários, de integração e de carga/resiliência); `cd ascii-engine-module && npm ci && npm run typecheck && npm run build` valida o motor isolado. O workflow `.github/workflows/ci.yml` executa essa matriz completa.

Backend real: `backend/` contém a aplicação FastAPI em monólito modular completo (Fases 1 a 5), com domínios em `backend/app/domains/`, cache/fila Redis com fallback em memória, workers concorrentes no `lifespan`, rate limit por escopo/IP, headers de segurança HTTP, ETL, gateway fiscal com HMAC/idempotência, scrapers com guarda SSRF por redirect, workflows multi-etapas de IA, ponte de eventos + callbacks HMAC com n8n, inspetores reais de CI/CD & Docker com RCA verificável e Console RAG híbrido/vetorial sobre a documentação e o código real do repositório. Além dos endpoints listados acima, há `/api/v1/gateway/capabilities`, `/api/v1/workflows/catalog`, `/api/v1/workflows/callbacks/{workflow_id}`, `/api/v1/jobs/*`, `/api/v1/scraping/*`, `/api/v1/ai-workflows/*`, `/api/v1/pipelines/*` e `/api/v1/rag/*` (detalhes em [`backend/ARCHITECTURE.md`](backend/ARCHITECTURE.md)). `docker-compose.yml` sobe API + n8n com segredos obrigatórios em `.env`. O `Dockerfile` da raiz ainda publica a versão atual na Vercel; `ci-cd.yml` constrói apenas a imagem do backend.

O palco `[ CENA 3D INTERATIVA ]` / `[ INTERACTIVE SCENE 3D ]` usa o motor WebGL2 3D de `ascii-engine-module/` (`assets/js/ascii-engine.bundle.js`) por meio de `assets/js/engine-adapter.js`, incluindo cenário cyberpunk em camadas, sombras PCF, vento ECS, bloom e DoF. A UI expõe apenas três modos de cena — `[ Dia ]`, `[ Noite ]`, `[ Com chuva ]` — ligados a `setPreset()`; o engine também oferece contorno por objeto (`setObjectOutline`), ainda não aplicado ao pinguim. `[ STACK // NEOFETCH ]` renderiza Tux 3D com `THREE.Group` via `getScene()`, com rotação horizontal contínua e nenhuma reação a mouse/toque; durante o carregamento ou em falha, `assets/js/neofetch.js` mostra um pinguim ASCII estático e simpático como placeholder, sem afetar o pinguim 3D já ativo. O wrapper do adapter expõe `create`, `mount`, `setPaused`, `setPreset`, `setAutoOrbit` e `destroy`, usa `ResizeObserver` e pausa cenas fora da viewport. Nenhum núcleo do motor é alterado pela integração.

O hero mostra a foto/retrato como cartão na coluna esquerda, abaixo do único título ASCII `ERON YAMAMOTO`, com o topo alinhado ao bloco de texto da direita (`eron@production:~$ whoami`). No footer há o controle de brilho da página (padrão `130%`, faixa `100–150%`), que substitui o antigo controle de contraste. Detalhes e histórico do dia em [`docs/changelog-2026-11-25.md`](docs/changelog-2026-11-25.md).
