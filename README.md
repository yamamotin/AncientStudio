# Eron Terminal — portfólio técnico interativo

Single-page, sem frameworks e sem build: HTML, CSS e um pouco de JavaScript puro com estética de terminal Linux. Inclui banner ASCII, simulador de CI/CD com um caminho de falha e RCA, playground de APIs em abas, bloco de stack estilo `neofetch` e console de comandos (`help`, `skills`, `experience`, `projects`, `contact`, `cv`, `clear`). Tudo o que aparece nos simuladores é fictício e sinalizado como tal.

Para editar, altere `index.html` (textos e ordem das seções), `assets/css/style.css` (variáveis no topo) e os módulos em `assets/js/`. Os currículos enviados pelo Eron estão em `assets/cv/`, e o JetBrains Mono usado localmente está em `assets/fonts/` com sua licença OFL — nada é carregado de CDNs.

Abra `index.html` diretamente para ver a versão em modo sim. Para usar a API Python real (endpoints `/api/v1/health`, `/api/v1/extract` e `/api/v1/invoices/parse`), rode `python3 api/server.py` e abra `http://localhost:8000`; o status no topo muda para `API ONLINE`. Com Docker: `docker build -t eron-terminal . && docker run -p 8000:8000 eron-terminal`.

Publicação: `.github/workflows/pages.yml` publica em `https://yamamotin.github.io/AncientStudio/` o mesmo commit de `main` que a Vercel usa. Para o workflow funcionar, em GitHub → Settings → Pages → Build and deployment → Source escolha **GitHub Actions**. A Vercel usa o `Dockerfile` (projeto `ancientstudio`, `https://ancientstudio.vercel.app/`); as duas hospedagens entregam exatamente os mesmos arquivos relativos. O job `verify-parity` roda **depois** do deploy, compara `build.txt` do Pages com `/api/v1/build` da Vercel e usa `continue-on-error: true`: divergência ou atraso de CDN gera aviso, nunca falha o deploy.

Testes: `.github/workflows/pr-tests.yml` roda `node --test tests/*.test.js` em PRs e em `main`. A base é modular (`tests/helpers/`, testes estáticos e de contrato do motor), sem dependências ou build; basta rodar `node --test tests/*.test.js` localmente (o script usa o runner nativo do Node).

Backend real (em migração): `backend/` contém a aplicação FastAPI modular com endpoints de ETL, gateway fiscal com HMAC/idempotência e integração autenticada com n8n. A estrutura-alvo, contratos e plano de integração frontend estão em `docs/architecture.md`; `docker-compose.yml` sobe API + n8n com segredos obrigatórios em `.env`. O `Dockerfile` da raiz ainda publica a versão atual na Vercel enquanto a integração não é concluída.

O palco `[ ASCII REALMS // SCENE ]` usa o motor real de `ascii-engine-module/` (PR #4, já consolidado em `main`) por meio de `assets/js/engine-adapter.js`. O wrapper expõe `create`, `mount`, `setPaused`, `setPreset`, `setCycle`, `setAutoOrbit` e `destroy`, observa redimensionamento com `ResizeObserver` e pausa cenas fora da viewport. O bundle e o adapter são carregados sob demanda, após interação/proximidade, para não atrasar o LCP; em WebGL por software permanece o fallback ASCII. O pinguim 3D de `[ STACK // NEOFETCH ]` é um `THREE.Group` real adicionado à mesma cena. Detalhes em `docs/engine-integration.md`; nenhum arquivo do núcleo do motor é alterado aqui.
